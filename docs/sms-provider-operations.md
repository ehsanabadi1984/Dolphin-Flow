# راهنمای عملیاتی تنظیمات پیامک

مسیر اصلی مدیریت سرویس پیامک از پنل ادمین Dolphin-Flow و بخش «تنظیمات سراسری پیامک» است. اجرای فرمان‌های Bootstrap برای راه‌اندازی عادی مدیر سامانه لازم نیست.

## ۱. پیش‌نیازهای زیرساختی

- Migration مربوط به `workflow.0081_smsdelivery_message_source_and_more` باید در استقرار برنامه اعمال شده باشد.
- وابستگی `cryptography` نصب باشد.
- دسترسی خروجی HTTPS سرور برنامه به API مگفا برقرار باشد.
- کلید رمزنگاری در محیط امن سرور تنظیم شده باشد.
- از دیتابیس نسخه پشتیبان معتبر تهیه شده باشد.

## ۲. کلید رمزنگاری

کلید Fernet را یک‌بار برای محیط موردنظر ایجاد و در متغیر محیطی خصوصی `SMS_CREDENTIALS_ENCRYPTION_KEY` قرار دهید. مقدار کلید نباید در Git، پنل ادمین، تیکت، پیام‌رسان، لاگ یا خروجی قابل‌اشتراک ثبت شود.

نکات حیاتی:

- تمام پردازه‌های Django، Daphne، Celery و Celery Beat باید دقیقاً از یک کلید یکسان استفاده کنند.
- فایل محیطی حاوی کلید باید فقط برای کاربر سرویس قابل‌خواندن باشد.
- از کلید نسخه پشتیبان امن و مستقل از دیتابیس نگهداری کنید. بکاپ دیتابیس بدون کلید برای بازیابی اعتبارنامه‌های رمز‌شده کافی نیست.
- پس از ثبت اعتبارنامه‌ها کلید را تغییر ندهید. گردش‌کار عملیاتی چرخش کلید و رمزگذاری مجدد نسخه‌های قبلی هنوز پیاده‌سازی نشده است. تغییر یا گم‌شدن کلید، رمزگشایی اعتبارنامه‌های ذخیره‌شده را ناممکن می‌کند.

## ۳. راه‌اندازی از پنل ادمین

مدیر ارشد سیستم وارد بخش «ارتباطات ← تنظیمات سراسری پیامک» می‌شود و مراحل زیر را انجام می‌دهد:

1. نام کاربری، رمز عبور، دامنه و شماره فرستنده مگفا را در فرم وارد و ذخیره می‌کند.
2. نشانی API و مهلت اتصال را در صورت نیاز تنظیم می‌کند.
3. گزینه «ذخیره و آزمایش اتصال» را انتخاب می‌کند. برنامه اعتبارنامه ذخیره‌شده را رمزگشایی کرده و درخواست GET به مسیر `/balance` مگفا می‌فرستد. این آزمون پیامک ارسال نمی‌کند و اپراتور را فعال نمی‌کند.
4. فقط پس از موفقیت آزمون، مدیر می‌تواند «ذخیره، آزمایش و فعال‌سازی اپراتور» را انتخاب کند.
5. پس از فعال‌شدن اپراتور، کلید «ارسال پیامک فعال باشد» را جداگانه روشن می‌کند.

رمز عبور در فرم به‌صورت آشکار نمایش داده نمی‌شود. برای حفظ رمز فعلی، فیلد رمز عبور باید خالی بماند. تغییر اعتبارنامه یا تنظیمات اتصال، نسخه جدیدی از پیکربندی رمز‌شده ایجاد می‌کند. اگر اپراتور فعال باشد و اطلاعات اتصال تغییر کند، برای جلوگیری از ارسال با اطلاعات آزمایش‌نشده، اپراتور و ارسال سراسری تا آزمایش و فعال‌سازی مجدد غیرفعال می‌شوند.

تمام این عملیات در پنل برای مدیر ارشد سیستم محدود شده است.

## ۴. تنظیمات تکمیلی

- قالب‌های اختصاصی پیامک از بخش «قالب‌های پیامک» در همان گروه تنظیمات ارتباطات مدیریت می‌شوند. هر قالب به یک مرحله و نوع اعلان تعلق دارد.
- سوابق فنی ارسال پیامک فقط برای مشاهده و بررسی در دسترس مدیر ارشد سیستم هستند.
- قوانین پیامک هر مرحله و نوع اعلان مستقل از کلید سراسری‌اند و باید جداگانه فعال شوند.
- ترجیح دریافت پیامک کاربر و شماره موبایل فعال و تأییدشده نیز باید برقرار باشد.
- فعال‌سازی اپراتور به‌تنهایی به معنی فعال‌شدن ارسال سراسری یا تمام قوانین مرحله‌ای نیست.

## ۵. سازگاری با ارسال‌های قدیمی

تا پایان دوره سازگاری، مقادیر محیطی `MAGFA_USERNAME`، `MAGFA_PASSWORD`، `MAGFA_DOMAIN` و `MAGFA_SENDER` را در محیط پردازه‌های ارسال نگه دارید. رکوردهای قدیمی `SMSDelivery` ممکن است هنوز نسخه Provider متصل نداشته باشند و مسیر سازگاری آن‌ها از تنظیمات محیطی استفاده می‌کند. این متغیرها برای ثبت و تغییر تنظیمات جدید از پنل لازم نیستند.

`MAGFA_API_BASE_URL` و `MAGFA_TIMEOUT` نیز می‌توانند مقدار پیش‌فرض زیرساختی داشته باشند؛ تنظیمات ثبت‌شده از پنل در نسخه Provider ذخیره می‌شوند.

## ۶. Bootstrap و بازیابی

فرمان `bootstrap_sms_provider` صرفاً ابزار پشتیبان برای راه‌اندازی اولیه یا بازیابی کنترل‌شده است و مسیر عادی مدیریت اپراتور محسوب نمی‌شود. این فرمان در صورت وجود نسخه جاری، اعتبارنامه‌های ذخیره‌شده را جایگزین نمی‌کند.

برای تغییر اعتبارنامه‌ها از پنل ادمین استفاده کنید؛ متغیرهای محیطی یا اجرای دوباره Bootstrap روش چرخش اعتبارنامه‌های ثبت‌شده نیستند.

## ۷. محدوده و هشدار عملیاتی

این راهنما مجوز اجرای Migration روی محیط عملیاتی، فعال‌سازی سراسری پیامک، روشن‌کردن قوانین مراحل، ارسال پیامک واقعی یا استقرار نسخه جدید نیست. هرکدام از این اقدامات نیازمند بررسی، پشتیبان‌گیری و تأیید جداگانه است.
