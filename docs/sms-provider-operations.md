# راهنمای عملیاتی راه‌اندازی درگاه پیامکی مگفا

این راهنما برای استقرار کنترل‌شده SMS Provider Registry است. اجرای مراحل روی محیط عملیاتی فقط پس از تهیه نسخه پشتیبان و تأیید مالک سرویس انجام شود.

## ۱. پیش‌نیازها

- کد برنامه شامل Migration مربوط به `workflow.0081_smsdelivery_message_source_and_more` باشد.
- وابستگی `cryptography` نصب باشد.
- اطلاعات معتبر حساب مگفا در اختیار مدیر سامانه باشد: نام کاربری، گذرواژه، دامنه و شماره فرستنده.
- دسترسی خروجی HTTPS سرور برنامه به API مگفا برقرار باشد.
- از دیتابیس نسخه پشتیبان معتبر تهیه شده باشد.

## ۲. ساخت و نگهداری کلید رمزنگاری

یک کلید Fernet بسازید:

```bash
python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

مقدار تولیدشده را فقط در فایل محیطی خصوصی سرور، در متغیر `SMS_CREDENTIALS_ENCRYPTION_KEY` قرار دهید. این کلید را در Git، تیکت، پیام‌رسان، لاگ یا خروجی قابل‌اشتراک قرار ندهید.

نکات حیاتی:

- برای تمام پردازه‌های Django، Daphne، Celery و Celery Beat که به اعتبارنامه‌های Registry نیاز دارند، دقیقاً یک کلید یکسان تنظیم کنید.
- فایل محیطی حاوی کلید باید فقط برای کاربر سرویس قابل‌خواندن باشد؛ برای نمونه مجوز فایل را به `600` محدود کنید.
- از کلید یک نسخه پشتیبان امن و مستقل از دیتابیس نگهداری کنید. بکاپ دیتابیس بدون کلید برای بازیابی اعتبارنامه‌های رمز‌شده کافی نیست.
- پس از ثبت اولین نسخه اعتبارنامه، کلید را تغییر ندهید. در نسخه فعلی پروژه، گردش‌کار عملیاتی چرخش کلید و رمزگذاری مجدد نسخه‌های قبلی پیاده‌سازی نشده است. تغییر یا گم‌شدن کلید، رمزگشایی اعتبارنامه‌های ذخیره‌شده را ناممکن می‌کند.

## ۳. متغیرهای محیطی

مقادیر زیر را در فایل محیطی خصوصی تنظیم کنید:

- `SMS_CREDENTIALS_ENCRYPTION_KEY`: کلید Fernet تولیدشده در مرحله قبل.
- `MAGFA_USERNAME`
- `MAGFA_PASSWORD`
- `MAGFA_DOMAIN`
- `MAGFA_SENDER`
- `MAGFA_API_BASE_URL`: در صورت استفاده از آدرس پیش‌فرض، `https://sms.magfa.com/api/http/sms/v2`.
- `MAGFA_TIMEOUT`: مهلت درخواست بر حسب ثانیه؛ مقدار پیش‌فرض ۱۰ است.

اعتبارنامه‌ها در Registry به‌صورت رمز‌شده ذخیره می‌شوند. تنظیمات اتصال مانند نشانی API و timeout در رکورد نسخه تنظیمات ذخیره می‌شوند و محرمانه محسوب نمی‌شوند.

تا پایان دوره سازگاری، مقادیر `MAGFA_USERNAME`، `MAGFA_PASSWORD`، `MAGFA_DOMAIN` و `MAGFA_SENDER` را در محیط پردازه‌های ارسال نگه دارید. رکوردهای قدیمی `SMSDelivery` ممکن است هنوز نسخه Provider متصل نداشته باشند و مسیر سازگاری آن‌ها از تنظیمات محیطی استفاده می‌کند. فقط پس از تعیین تکلیف و تخلیه ارسال‌های قدیمی می‌توان درباره حذف این مقادیر تصمیم گرفت.

## ۴. بررسی پیش از Bootstrap

از پوشه backend اجرا کنید:

```bash
python manage.py check
python manage.py showmigrations workflow
```

اطمینان حاصل کنید Migration شماره `0081` اعمال شده است. اگر اعمال نشده، ابتدا برنامه استقرار و پشتیبان‌گیری دیتابیس را طبق رویه مصوب اجرا کنید؛ این راهنما مجوز اجرای Migration روی محیط عملیاتی نیست.

## ۵. ثبت تنظیمات بدون فعال‌سازی

ابتدا دستور را بدون گزینه فعال‌سازی اجرا کنید:

```bash
python manage.py bootstrap_sms_provider
```

این دستور اعتبارنامه‌ها را اعتبارسنجی می‌کند، کلید رمزنگاری را بررسی می‌کند و در صورت نبود نسخه جاری، آن را به‌صورت رمز‌شده ثبت می‌کند. در این حالت Provider جدید غیرفعال می‌ماند.

دستور idempotent است: اگر نسخه جاری وجود داشته باشد، آن را حفظ می‌کند و اعتبارنامه‌های جدید محیط را جایگزین نمی‌کند. بنابراین تغییر متغیرهای محیطی و اجرای مجدد دستور، روش تغییر اعتبارنامه‌های ثبت‌شده نیست.

برای بررسی وضعیت بدون نمایش رازها:

```bash
python manage.py shell -c "from workflow.models import SMSProviderConfiguration; p=SMSProviderConfiguration.objects.get(code='magfa'); r=p.revisions.get(is_current=True); print({'active': p.is_active, 'revision': r.version, 'encrypted_credentials_present': bool(r.credentials_ciphertext)})"
```

## ۶. آزمون اتصال و فعال‌سازی Provider

پس از تأیید مالک حساب و مقادیر تنظیمات، اجرا کنید:

```bash
python manage.py bootstrap_sms_provider --activate
```

گزینه `--activate` یک درخواست GET به مسیر `/balance` در API مگفا می‌فرستد. این آزمون موجودی را می‌خواند و پیامک آزمایشی ارسال نمی‌کند. اگر آزمون اتصال ناموفق باشد، Provider فعال نمی‌شود.

فعال‌سازی Provider به‌تنهایی ارسال پیامک را روشن نمی‌کند:

- کلید سراسری پیامک در `WorkflowSMSSettings` به‌صورت پیش‌فرض خاموش است.
- قوانین پیامک هر مرحله و نوع اعلان نیز به‌صورت پیش‌فرض خاموش‌اند.
- ترجیح دریافت پیامک کاربر و شماره موبایل فعال و تأییدشده نیز باید برقرار باشد.

روشن‌کردن این گزینه‌ها باید جداگانه و پس از تأیید کسب‌وکار انجام شود. ابتدا با یک دامنه محدود و کاربران/مراحل آزمایشی مورد تأیید، ارسال واقعی را کنترل کنید.

## ۷. تغییر اعتبارنامه‌ها و بازیابی

- اجرای دوباره Bootstrap نسخه جاری را تغییر نمی‌دهد.
- در نسخه فعلی، فرایند چرخش اعتبارنامه یا کلید از طریق فرمان عملیاتی آماده نشده است؛ برای تغییر، ابتدا باید گردش‌کار نسخه جدید و آزمون‌شده پیاده‌سازی شود.
- برای بازیابی دیتابیس، کلید دقیق متناظر با داده‌های رمز‌شده نیز لازم است.
- هرگز برای رفع مشکل رمزگشایی، کلید جدیدی تولید و جایگزین کلید قبلی نکنید؛ این کار داده‌های موجود را قابل‌رمزگشایی نمی‌کند.

## ۸. محدوده این راهنما

این راهنما صرفاً مراحل ثبت و فعال‌سازی Provider را توضیح می‌دهد. اجرای آن به‌معنای اجرای Migration، فعال‌سازی سراسری پیامک، روشن‌کردن قوانین مراحل، ارسال پیامک واقعی یا استقرار نسخه جدید نیست. هرکدام از این اقدامات نیازمند بررسی و تأیید جداگانه است.
